## From prompt to pull request

| **01 · Connect** | **02 · File an issue** | **03 · The fleet solves it** | **04 · Review the PR** |
| --- | --- | --- | --- |
| Install Ridgeline on the repos you want help with. Issues on. That’s the setup. | Describe the work in plain English and add the `ridgeline` label. | Agents read the codebase, write the change, and check their work. | Every result arrives as a pull request. Rerun with more context anytime. |

```bash
gh issue create --label ridgeline
```

## What you get

- **Many minds on every task.** Agents compete. The run you review is the strongest attempt.
- **GitHub native.** Issues in, pull requests out. Ridgeline works in the flow you already use.
- **The whole loop.** From an unfamiliar codebase to a verified change.
- **You stay in control.** Inspect the diff, send feedback, or rerun. Nothing lands until you merge it.
